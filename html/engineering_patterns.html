Engineering Patterns (Staff Recognition)

These are not LeetCode patterns. They are the recurring shapes you should recognize in design reviews, RFCs, and incidents — the systems analogue of “sliding window vs two pointers.” Drill the when until naming the pattern is automatic.

EE bridge

Think protection relays, isolation, and control loops: rate limits are current limiters, circuit breakers are trip coils, bulkheads are compartmentalized buses, backpressure is a governor, and the outbox is dual-write avoidance — one atomic commit, then async publish.

1. Cache-Aside

data

App reads cache → on miss, load DB → fill cache. Writes update DB then invalidate (or update) cache. App owns consistency policy.

read-heavy path TTL + invalidation stampede risk
Staff check

What is the stale window? Who wins on thundering herd? Is invalidation race-safe with concurrent writers?

2. Idempotency Keys

API

Client sends a unique key with a mutating request. Server stores result keyed by that id so retries return the same outcome instead of double-charging / double-creating.

payments / create at-least-once delivery client retries

3. Transactional Outbox

messaging

In the same DB transaction as the business write, insert an outbox row. A relay publishes outbox events to the bus. Avoids “DB committed but message lost” dual-write.

DB + publish exactly-once illusion CDC / relay

4. Circuit Breaker

resilience

After error threshold, open the circuit and fail fast (or serve fallback). Half-open probes recovery. Protects callers from waiting on a dead dependency.

cascading failure timeout storms fallback path

5. Rate Limiting

capacity

Token bucket / sliding window / leaky bucket to protect capacity. Decide: per user, per IP, per API key, global.

429 / quota abuse protection fairness

6. Saga / Compensation

workflow

Multi-service workflow without distributed 2PC: each step has a compensating action. Choreography (events) vs orchestration (central coordinator).

multi-service booking compensate / undo no 2PC

7. Optimistic Concurrency

consistency

Version column or ETag: update only if version matches. On conflict, reload and retry. Beats coarse locking for low contention.

version / ETag lost update COMPARE-AND-SWAP

8. Bulkhead Isolation

isolation

Separate thread pools / connection pools / queues per dependency so one slow partner cannot exhaust the whole process.

pool per dependency blast radius noisy neighbor

9. Backpressure

flow control

When consumers cannot keep up, producers must slow, drop, or shed load — bounded queues, TCP windows, reactive streams, load-shed 503s. Unbounded buffers are a delayed outage.

bounded queue load shed producer slowdown
How to practice

In every systems design, force yourself to name which of these apply. Pair with Systems Design and Staff-Level Skills. Algorithm drills stay on Algorithm Patterns / Practice Arena.
