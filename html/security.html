Security & Cryptography

Adversarial thinking. Assume a hostile channel and a curious insider.

EE bridge

Security is signal integrity under an adversary who crafts inputs — like EMI, but intentional. Crypto provides sealed envelopes; systems still need correct key distribution and trust boundaries.

Threat modeling

STRIDE: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege. Draw trust boundaries; ask what crosses them.

Crypto primitives (roles, not math proofs)

  • Hash: integrity fingerprint (not encryption).
  • MAC / HMAC: integrity + authenticity with a key.
  • AEAD (AES-GCM): confidentiality + integrity together.
  • Public-key: key exchange / signatures; expensive — wrap symmetric keys.
  • TLS: handshake establishes keys; then AEAD records.
Don’t

Don’t invent crypto. Don’t use ECB. Don’t roll your own JWT validation. Prefer boring high-level libraries.

Auth & web risks

Authentication = who you are. Authorization = what you may do. Server must enforce both. OWASP-style hits: injection, XSS, CSRF, SSRF, broken access control, misconfig, vulnerable deps. 

// mental checklist for every endpoint
1. Is the caller authenticated?
2. Is the caller authorized for THIS resource?
3. Are inputs validated / parameterized (SQL/cmd)?
4. Is output encoded for the context (HTML/JS)?
5. Are secrets out of logs and repos?
