Sliding Window

Time: O(n) Space: O(1) or O(k)
technique
Why "Sliding Window"?

Picture a physical window frame sliding along a row of data. The window has a fixed width, and you slide it one position at a time, like a train window showing a fixed-width view of the passing scenery. From signal processing: a "windowed" analysis examines a subset of data at a time.

Maintain a window (subarray/substring) that slides across the input. Instead of recalculating from scratch for each position, update incrementally. Converts O(n*k) brute force into O(n).

When to Use

contiguous subarray/substring max/min sum of size k smallest/longest subarray character frequency constraints "consecutive", "window"

Animation: Max Sum of k=3

Fixed Window (k=3) on [2, 1, 5, 1, 3, 2]
Press Play or Next to begin.

Approach

  1. Identify what the window tracks (sum, frequency map, count)
  2. Decide: fixed-size or variable-size window?
  3. Initialize window state for the first window
  4. Slide: add right element, remove left element
  5. At each valid window, update the answer

Code Template

def sliding_window_fixed(arr, k):
    window_sum = sum(arr[:k])
    best = window_sum
    for i in range(k, len(arr)):
        window_sum += arr[i] - arr[i - k]
        best = max(best, window_sum)
    return best
Pitfalls
  • Off-by-one on window boundaries (left inclusive, right inclusive vs exclusive)
  • Forgetting to handle the case where no valid window exists
  • Not initializing window state correctly for the first window

Canonical Problems

  • Longest Substring Without Repeating Characters
  • Minimum Window Substring
  • Sliding Window Maximum (with deque)
  • Permutation in String

Two Pointers

Time: O(n) Space: O(1)
technique
Why "Two Pointers"?

Literally two index markers (pointers) that walk through the data structure. Like two fingers on a ruler, each moving independently. Named for the mental image of pointing at two positions simultaneously.

Use two pointers that move through the data structure in a coordinated way. Typically one from each end (converging), or both from the start at different speeds. Reduces O(n^2) to O(n).

When to Use

sorted array + target sum remove duplicates in-place palindrome check linked list cycle detection "pair", "sorted", "partition"

Animation: Find Pair Summing to 10

Converging Pointers on [1, 2, 3, 4, 6, 8, 11]
Press Play or Next to begin.

Approach

  1. Identify pointer strategy: opposite ends, same direction, or two arrays
  2. Define the movement rule: when does each pointer advance?
  3. Define the termination condition
  4. Handle edge cases: empty input, single element

Code Template

def two_sum_sorted(arr, target):
    left, right = 0, len(arr) - 1
    while left < right:
        s = arr[left] + arr[right]
        if s == target: return [left, right]
        elif s < target: left += 1
        else: right -= 1
    return []
Pitfalls
  • Forgetting that converging pointers require sorted input
  • Infinite loops from not advancing at least one pointer each iteration
  • Off-by-one: left < right vs left <= right depends on the problem

Canonical Problems

  • Two Sum II (sorted)
  • 3Sum
  • Container With Most Water
  • Trapping Rain Water
  • Valid Palindrome

Binary Search

Time: O(log n) Space: O(1)
technique
Why "Binary Search"?

"Binary" = two parts. Each step divides the search space in two (bi-section). From Latin "binarius" (consisting of two). You always choose one of two halves.

Repeatedly halve the search space by checking a condition at the midpoint. Not just for sorted arrays -- works on any monotonic predicate. "Binary search on the answer" applies when you can frame the problem as finding the smallest/largest X satisfying a condition.

When to Use

sorted array lookup find minimum X satisfying condition O(log n) time requirement search space halvable by midpoint check

Animation: Search for 7

Binary Search in [1, 3, 5, 7, 9, 11, 13, 15]
Press Play or Next to begin.

Approach

  1. Define the search space: [lo, hi]
  2. Define the predicate: condition(mid) -> bool
  3. Determine: searching for leftmost True or rightmost True?
  4. Choose the right template to avoid off-by-one
  5. Verify: does lo converge to the right answer?

Code Template

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1
Pitfalls
  • Off-by-one: lo < hi vs lo <= hi -- pick one template and stick with it
  • Integer overflow: use lo + (hi - lo) // 2
  • Infinite loops: ensure lo or hi changes every iteration

Canonical Problems

  • Binary Search
  • Search in Rotated Sorted Array
  • Koko Eating Bananas
  • Median of Two Sorted Arrays

Breadth-First Search

Time: O(V + E) Space: O(V)
traversal
Why "Breadth-First Search"?

"Breadth" = width. Explores wide before deep -- like water rippling outward from a stone dropped in a pond. Named because it explores all neighbors (breadth) at the current depth before going deeper.

Explore nodes level by level outward from the source. Uses a queue. Guarantees shortest path in unweighted graphs. Also used for level-order tree traversal and multi-source BFS.

When to Use

shortest path (unweighted) level-order traversal minimum steps to target spreading problems (fire, infection) "nearest", "level by level"

Animation: Level-by-Level Traversal

BFS on a 6-Node Graph
Press Play or Next to begin.

Approach

  1. Initialize queue with starting node(s), mark as visited
  2. Process level by level (track depth if needed)
  3. For each node: explore all neighbors, enqueue unvisited ones
  4. Stop when target found or queue empty

Code Template

from collections import deque

def bfs(graph, start):
    queue = deque([(start, 0)])
    visited = {start}
    while queue:
        node, dist = queue.popleft()
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                queue.append((nb, dist + 1))
Pitfalls
  • Mark nodes visited BEFORE enqueueing (not after dequeue) to avoid duplicates
  • Use deque, not list.pop(0) which is O(n)
  • For level-by-level: snapshot queue size at start of each level

Canonical Problems

  • Number of Islands
  • Rotting Oranges
  • Word Ladder
  • Binary Tree Level Order Traversal

Depth-First Search

Time: O(V + E) Space: O(h) or O(V)
traversal
Why "Depth-First Search"?

"Depth" = how far down. Explores deep before wide -- like a miner digging a single tunnel as deep as possible before trying another. Named because it goes to maximum depth first.

Explore as deep as possible along each branch before backtracking. Uses recursion (call stack) or an explicit stack. Natural fit for tree problems, connected components, and cycle detection.

When to Use

tree traversal (pre/in/post) connected components cycle detection explore all possibilities "all paths", "component"

Approach

  1. Choose recursive or iterative
  2. Define: what does visiting a node mean?
  3. Base case: null node, visited node, or boundary
  4. Recursive case: process current, recurse on children
  5. For graphs: maintain visited set

Code Template

def dfs(root):
    if not root: return
    process(root)          # preorder
    dfs(root.left)
    dfs(root.right)
Pitfalls
  • Stack overflow on deep recursion (Python limit ~1000)
  • For directed graphs: need 3-state visited for cycle detection
  • Forgetting to un-visit in backtracking problems

Topological Sort

Time: O(V + E) Space: O(V + E)
technique
Why "Topological Sort"?

"Topology" = study of spatial relationships and ordering (from Greek "topos" = place). A topological sort arranges nodes so that every directed edge points forward. Named because it reflects the "topology" (connection structure) of the graph, not numeric values.

Linear ordering of vertices in a DAG such that for every edge u->v, u comes before v. Kahn's algorithm uses BFS with in-degree tracking. If a cycle exists, no valid ordering is possible.

When to Use

tasks with prerequisites build/compile order cycle detection (directed) "prerequisite", "dependency" "ordering", "schedule"

Animation: Kahn's Algorithm

Course Prerequisites: Kahn's Algorithm with In-Degree
Press Play or Next to begin.

Approach

  1. Build adjacency list and compute in-degree for each node
  2. Enqueue all nodes with in-degree 0
  3. Process queue: reduce in-degree of neighbors
  4. If neighbor's in-degree becomes 0, enqueue it
  5. If result has fewer nodes than total, there is a cycle

Code Template

from collections import deque, defaultdict

def topo_sort(n, edges):
    graph = defaultdict(list)
    in_deg = [0] * n
    for u, v in edges:
        graph[u].append(v)
        in_deg[v] += 1
    q = deque(i for i in range(n) if in_deg[i] == 0)
    order = []
    while q:
        node = q.popleft()
        order.append(node)
        for nb in graph[node]:
            in_deg[nb] -= 1
            if in_deg[nb] == 0: q.append(nb)
    return order if len(order) == n else []
Pitfalls
  • Confusing edge direction: "A prereq of B" means edge A->B
  • Not handling disconnected components
  • DFS version needs 3-state coloring for cycle detection

Canonical Problems

  • Course Schedule / Course Schedule II
  • Alien Dictionary
  • Parallel Courses

Dynamic Programming

Time: O(n*m) Space: O(n*m) or O(n)
optimization
Why "Dynamic Programming"?

Named by Richard Bellman in the 1950s. "Dynamic" was chosen to sound impressive and avoid government pushback (his boss hated the word "research"). "Programming" meant planning/scheduling (like "linear programming"), not coding. It's really "multi-stage decision optimization" but Bellman wanted a name that couldn't be criticized.

Break a problem into overlapping subproblems, solve each once, store results. The key is defining the state (what dp[i][j] represents) and the recurrence. Bottom-up (tabulation) or top-down (memoization).

When to Use

"minimum cost", "maximum profit" "number of ways" overlapping subproblems optimal substructure take or skip decisions

Animation: Edit Distance

Edit Distance: "horse" -> "ros" (simplified 4x4 grid)
Press Play or Next to begin.

Approach

  1. Define the state: what does dp[i][j] represent?
  2. Write the recurrence relation BEFORE coding
  3. Identify base cases
  4. Determine fill order
  5. Optimize space if possible

Code Template

def edit_distance(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i
    for j in range(n+1): dp[0][j] = j
    for i in range(1, m+1):
        for j in range(1, n+1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    return dp[m][n]
Pitfalls
  • Imprecise state definition leads to wrong recurrence
  • Wrong base cases (off-by-one with 0/1-indexed dp)
  • Confusing "ending at i" vs "using elements 0..i"

Canonical Problems

  • Climbing Stairs
  • Coin Change
  • Longest Increasing Subsequence
  • Edit Distance
  • Word Break

Greedy

Time: O(n log n) Space: O(1)
optimization
Why "Greedy"?

The algorithm is "greedy" -- it always grabs the best-looking option right now without considering the future. Like a greedy person taking the biggest piece of cake at each step. Named for this short-sighted, grab-the-best-now behavior.

Make the locally optimal choice at each step. Only works when the greedy choice property holds. Often requires sorting first. When in doubt, try DP instead.

When to Use

interval scheduling local optimal = global optimal sorting + sequential selection "minimum number of" "maximum non-overlapping"

Animation: Interval Scheduling

Select Maximum Non-Overlapping Intervals (sorted by end time)
Press Play or Next to begin.

Approach

  1. Sort the input (by start time, end time, ratio, etc.)
  2. Iterate and make the greedy choice at each step
  3. PROVE it works: exchange argument or greedy stays ahead
  4. If you cannot prove it, consider DP instead

Code Template

def max_intervals(intervals):
    intervals.sort(key=lambda x: x[1])
    count, last_end = 0, float('-inf')
    for start, end in intervals:
        if start >= last_end:
            count += 1
            last_end = end
    return count
Pitfalls
  • Assuming greedy works without proof -- many problems look greedy but need DP
  • Sorting by the wrong key (start time vs end time matters!)
  • Not handling ties correctly

Canonical Problems

  • Jump Game / Jump Game II
  • Non-overlapping Intervals
  • Merge Intervals
  • Task Scheduler

Backtracking

Time: O(2^n) or O(n!) Space: O(n)
technique
Why "Backtracking"?

Literally "tracking back" -- retracing your steps when you hit a dead end. Like walking a maze: go forward, hit a wall, back up to the last junction, try another path. Named for the act of going backward to undo a bad choice.

Systematically explore all candidates by building choices incrementally and abandoning a path as soon as it is invalid. DFS on a decision tree with pruning.

When to Use

generate all permutations/combinations N-Queens, Sudoku word search in grid "all possible", "enumerate"

Animation: 4-Queens

4-Queens: Place Queens, Backtrack on Conflict
Press Play or Next to begin.

Approach

  1. Define the decision tree: what choices at each step?
  2. Template: choose -> explore -> un-choose
  3. Base case: when is a candidate complete?
  4. Pruning: when can you skip a branch?
  5. Track state: what gets modified and needs restoration?

Code Template

def backtrack(candidates):
    result = []
    def helper(start, current):
        if is_solution(current):
            result.append(current[:])
            return
        for i in range(start, len(candidates)):
            current.append(candidates[i])   # choose
            helper(i + 1, current)          # explore
            current.pop()                    # un-choose
    helper(0, [])
    return result
Pitfalls
  • Forgetting to copy when adding to results (current[:] not current)
  • Forgetting to un-choose (restore state after recursion)
  • Not pruning -- backtracking without pruning is just brute force

Canonical Problems

  • Subsets / Permutations
  • Combination Sum
  • N-Queens
  • Word Search
  • Sudoku Solver

Heap / Priority Queue

Time: O(n log k) Space: O(k) or O(n)
structure
Why "Heap / Priority Queue"?

"Heap" = a pile. The data structure looks like a pile/mound shape (complete binary tree). "Priority Queue" = a queue where the most important item comes out first, like an ER triage system. Named for the heap-ordered tree shape (parent >= children).

Data structure supporting O(log n) insert and extract-min/max, O(1) peek. Use when you repeatedly need the smallest or largest element from a dynamic collection.

When to Use

K-th largest/smallest merge K sorted lists streaming median process by priority "top K", "K-th"

Animation: Build Min-Heap and Extract

Build Min-Heap from [4, 10, 3, 5, 1], then Extract Min
Press Play or Next to begin.

Approach

  1. Identify: min or max? (Python heapq is min-heap; negate for max)
  2. For K-th largest: maintain a min-heap of size K
  3. For streaming median: two heaps (max-heap lower, min-heap upper)
  4. For K-way merge: push first element of each list, pop-and-push-next

Code Template

import heapq

def top_k(nums, k):
    return heapq.nsmallest(k, nums)

def merge_k(lists):
    heap = []
    for i, lst in enumerate(lists):
        if lst: heapq.heappush(heap, (lst[0], i, 0))
    result = []
    while heap:
        val, li, ei = heapq.heappop(heap)
        result.append(val)
        if ei+1 < len(lists[li]):
            heapq.heappush(heap, (lists[li][ei+1], li, ei+1))
    return result
Pitfalls
  • Python heapq is min-heap only -- negate for max-heap
  • Tuple comparison: if first elements tie, Python compares second -- can crash
  • Solution: use (value, unique_counter, object) tuples

Canonical Problems

  • Kth Largest Element
  • Top K Frequent Elements
  • Merge K Sorted Lists
  • Find Median from Data Stream

Monotonic Stack

Time: O(n) Space: O(n)
structure
Why "Monotonic Stack"?

"Monotonic" = single direction (from Greek "monos" = single + "tonos" = stretching/direction). The stack maintains elements in strictly increasing or decreasing order. Named because the values in the stack are always monotonically ordered.

A stack maintaining elements in strictly increasing or decreasing order. When a new element violates order, pop until invariant restored. Popped elements have found their "answer". Converts O(n^2) to O(n).

When to Use

next greater/smaller element largest rectangle in histogram stock span daily temperatures "next greater", "histogram"

Animation: Next Greater Element

Next Greater Element for [2, 1, 5, 6, 2, 3]
Press Play or Next to begin.

Approach

  1. Decide: monotonic increasing or decreasing?
  2. For "next greater": use decreasing stack (pop when new > top)
  3. Iterate; while stack non-empty and current violates monotonicity: pop
  4. Push current element (or index) onto stack
  5. Remaining elements have no answer (use -1)

Code Template

def next_greater(nums):
    n = len(nums)
    result = [-1] * n
    stack = []
    for i in range(n):
        while stack and nums[stack[-1]] < nums[i]:
            result[stack.pop()] = nums[i]
        stack.append(i)
    return result
Pitfalls
  • Confusing increasing vs decreasing stack
  • Forgetting sentinel to flush remaining stack elements
  • Width calculation in histogram: i - stack[-1] - 1

Canonical Problems

  • Daily Temperatures
  • Next Greater Element I & II
  • Largest Rectangle in Histogram
  • Stock Span Problem

Union Find (Disjoint Set)

Time: O(alpha(n)) per op Space: O(n)
structure
Why "Union-Find / Disjoint Set"?

"Union" = merge two sets. "Find" = which set does this element belong to? Named directly after its two operations. "Disjoint Set" = sets that don't overlap (disjoint = not joined).

Track elements partitioned into disjoint sets. Near-O(1) union and find with path compression and union by rank. Use when dynamically merging groups and checking membership.

When to Use

dynamic connectivity merge groups incrementally count connected components Kruskal's MST "connected", "union", "same set"

Animation: Union Operations with Path Compression

6 Nodes: Union Operations Merging Sets
Press Play or Next to begin.

Approach

  1. Initialize: each element is its own parent
  2. Find: follow parent pointers to root, apply path compression
  3. Union: find roots of both, merge smaller into larger (by rank)
  4. Track component count: decrement on each successful union

Code Template

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    def union(self, x, y):
        px, py = self.find(x), self.find(y)
        if px == py: return
        if self.rank[px] < self.rank[py]: px, py = py, px
        self.parent[py] = px
        if self.rank[px] == self.rank[py]: self.rank[px] += 1
Pitfalls
  • Forgetting path compression (makes find O(n) instead of O(alpha(n)))
  • Use union by rank OR size, not both -- pick one
  • For string/object keys: use a dict instead of list for parent

Canonical Problems

  • Number of Connected Components
  • Redundant Connection
  • Accounts Merge
  • Graph Valid Tree

Trie (Prefix Tree)

Time: O(L) per op Space: O(total chars)
structure
Why "Trie / Prefix Tree"?

"Trie" comes from "retrieval" (pronounced "try" by creator Edward Fredkin, 1960). It's a tree where each path from root spells out a prefix of stored strings. Named for its purpose: information retrieval by prefix.

Tree where each node represents a character and paths from root spell prefixes. Enables O(L) lookup/insert where L is word length, regardless of dictionary size.

When to Use

prefix matching / autocomplete word dictionary with prefix queries word search on board (trie + DFS) "prefix", "dictionary"

Animation: Insert "cat", "car", "card"

Building a Trie: Insert "cat", "car", "card"
Press Play or Next to begin.

Approach

  1. Build trie: for each word, walk/create nodes character by character
  2. Mark end-of-word nodes
  3. Search: walk trie following character path
  4. Prefix search: same as search but do not require is_end

Code Template

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    def __init__(self): self.root = TrieNode()
    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True
Pitfalls
  • Memory-heavy: each node has a dict of children
  • For board problems: prune trie after finding words
  • Do not confuse search (exact match) with starts_with (prefix match)

  • Word Search II

Prefix Sum

Time: O(n) build, O(1) query Space: O(n)
technique
Why "Prefix Sum"?

"Prefix" = the beginning part of something. A prefix sum at position i is the sum of all elements from the start (prefix) up to position i. Named because each entry stores the cumulative sum of the prefix ending at that index.

Precompute cumulative sums so any subarray sum is O(1). prefix[i] = sum(arr[0..i-1]). Then sum(arr[l..r]) = prefix[r+1] - prefix[l]. Extends to 2D, XOR, product.

When to Use

multiple subarray sum queries "subarrays with sum equal to K" range sum queries "cumulative", "subarray sum"

Animation: Build Prefix Sum, Range Query [1,3]

Prefix Sum of [1, 2, 3, 4, 5] and Range Query
Press Play or Next to begin.

Approach

  1. Build prefix array: prefix[0] = 0, prefix[i] = prefix[i-1] + arr[i-1]
  2. Subarray sum [l, r] = prefix[r+1] - prefix[l]
  3. For "count subarrays with sum K": hash map of prefix sums

Code Template

def prefix_sum(nums):
    prefix = [0] * (len(nums) + 1)
    for i in range(len(nums)):
        prefix[i+1] = prefix[i] + nums[i]
    def query(l, r):
        return prefix[r+1] - prefix[l]
    return query
Pitfalls
  • Off-by-one: prefix has n+1 elements, prefix[0] = 0
  • For "sum equals K": initialize hash map with {0: 1}
  • Does not work for subarray product directly

Canonical Problems

  • Subarray Sum Equals K
  • Range Sum Query
  • Product of Array Except Self

Hash Map Patterns

Time: O(n) Space: O(n)
structure
Why "Hash Map"?

"Hash" = to chop/mix up. A hash function "hashes" (chops/scrambles) a key into a number (index). From the culinary term -- like making a hash (mixed dish) from ingredients. The key is "hashed" into a seemingly random but deterministic position.

Use hash maps for O(1) lookup/insert to replace O(n) scans. Common patterns: complement lookup (Two Sum), frequency counting, grouping by canonical key, and caching.

When to Use

O(1) lookup needed Two Sum complement check frequency counting group by key (anagrams) "find pair", "group by"

Approach

  1. Identify what to store: element->index, element->count, pattern->group
  2. Single-pass when possible: check then insert (Two Sum)
  3. For frequency: Counter or defaultdict(int)
  4. For grouping: defaultdict(list), key = canonical form

Code Template

from collections import defaultdict

def group_anagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        key = tuple(sorted(s))
        groups[key].append(s)
    return list(groups.values())
Pitfalls
  • Mutable objects (lists) cannot be dict keys -- convert to tuples
  • For sliding window + hash map: decrement/remove when shrinking
  • Hash collisions rare in practice but exist in theory

Dijkstra's Shortest Path

Time: O((V+E) log V) Space: O(V + E)
technique
Why "Dijkstra's Algorithm"?

Named after Edsger W. Dijkstra, the Dutch computer scientist who invented it in 1956 (published 1959). He conceived it in 20 minutes at a cafe in Amsterdam while thinking about the shortest route between Rotterdam and Groningen. Pronounced "DIKE-struh".

Find shortest paths from source to all nodes in a weighted graph with non-negative edges. Uses a min-heap to always process the nearest unvisited node. Greedy approach that works because non-negative weights guarantee correctness.

When to Use

shortest path (weighted, non-negative) minimum cost to destination network delay time "weighted graph" NOT for negative weights

Animation: Shortest Path Discovery

Dijkstra on 5-Node Weighted Graph
Press Play or Next to begin.

Approach

  1. Initialize: dist[source] = 0, all others = infinity
  2. Push (0, source) to min-heap
  3. Pop minimum distance node from heap
  4. If already visited with shorter distance, skip (lazy deletion)
  5. For each neighbor: if new distance < known, update and push

Code Template

import heapq

def dijkstra(graph, src):
    dist = {src: 0}
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist.get(u, float('inf')): continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist
Pitfalls
  • Does not work with negative edge weights
  • Must use lazy deletion (skip stale heap entries)
  • Do not confuse with BFS -- BFS is unweighted, Dijkstra is weighted

Canonical Problems

  • Network Delay Time
  • Cheapest Flights Within K Stops
  • Path with Minimum Effort
  • Swim in Rising Water

Binary Search on Answer

Time: O(check · log R) Space: O(1)
optimization
EE bridge

Like successive-approximation ADC / binary search on a threshold: the feasibility line is monotone (FFF…TTT), so each mid discards half the answer range.

Distinct from binary search on a sorted array index. Here the answer is a number on a monotone feasibility line — you invent can(mid) and search for the boundary.

When to Use

minimize maximum / maximize minimum capacity / speed / allocation monotone can(x) Koko / ship packages / split array

Code Template

def binary_search_answer(lo, hi, can):
    ans = hi
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return ans
Pitfalls
  • can(x) must be monotone — otherwise BS is wrong
  • First True vs last False off-by-one

Sweep Line / Intervals

Time: O(n log n) Space: O(n)
technique
EE bridge

Like counting concurrent signals on a timeline: rising edges (+1) and falling edges (−1); the running sum is instantaneous load — same idea as peak concurrent sessions in a service.

When to Use

meeting rooms / platforms max overlap / concurrency skyline / car pooling load over time

Code Template

def max_concurrent(intervals):
    events = []
    for s, e in intervals:
        events.append((s, 1))
        events.append((e, -1))
    events.sort(key=lambda x: (x[0], x[1]))
    cur = best = 0
    for _, d in events:
        cur += d
        best = max(best, cur)
    return best

Linked List Techniques

Time: O(n) Space: O(1)
structure

Dummy head, fast/slow (tortoise-hare), reverse, merge. Small API surface — easy to fumble under pressure until muscle memory.

When to Use

reverse / rotate list cycle detection (Floyd) middle / nth from end merge sorted lists

Code Template

def reverse_list(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    return prev

Bit Manipulation

Time: O(n) Space: O(1)
technique
EE bridge

Flags, permission masks, and protocol bitfields — same mental model as register bit packing. XOR cancels pairs like differential signaling nulling common mode.

When to Use

single number (XOR) bitmask subsets (n ≤ 20) power of two / popcount flag packs / permissions

Code Template

def single_number(nums):
    x = 0
    for n in nums:
        x ^= n
    return x

Difference Array

Time: O(n + u) Space: O(n)
technique
EE bridge

Inverse of prefix/integration: encode a step impulse at L and −impulse at R+1, then integrate once. Batch range writes without touching every cell each time.

When to Use

many range increments then read final array corporate flight bookings batch config over ranges

Code Template

def apply_range_updates(n, updates):
    diff = [0] * (n + 1)
    for L, R, val in updates:
        diff[L] += val
        if R + 1 < len(diff):
            diff[R + 1] -= val
    out, run = [0] * n, 0
    for i in range(n):
        run += diff[i]
        out[i] = run
    return out
